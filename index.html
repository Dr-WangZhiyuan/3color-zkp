3-Coloring Zero-Knowledge Proof

Interactive demonstration of the Commit-Challenge-Response protocol using graph 3-coloring

The Problem

A graph G is 3-colorable if its vertices can be coloured with 3 colours (Red, Green, Blue) such that no two adjacent vertices share the same colour. Prover P claims to know such a colouring.

Fact 1: Permutation preserves validity

Swapping colours (e.g., all Red→Blue, Blue→Red) still gives a valid 3-colouring. P uses this to create a fresh disguise each round.

Fact 2: Invalid colouring is detectable

If G is not validly coloured, at least one edge has matching colours on both ends. V can catch this by checking edges.

Zero-Knowledge Proof (ZKP) Properties

A ZKP involves two parties: the Prover (P) and the Verifier (V). Both share a common input, the statement to be proven (e.g., "P knows a valid 3-colouring of graph G"). The 3-coloring protocol illustrates the three properties of ZKP.

Completeness

In 3-coloring: Honest P has a valid colouring. After any random permutation, every edge still connects two differently-coloured vertices (Fact 1). V always accepts, across any number of rounds.

If P is honest, P will eventually convince V that the statement is true.

Soundness

In 3-coloring: Dishonest P has an invalid colouring with at least one bad edge where both vertices share the same colour (Fact 2). Each round, V might randomly pick that edge. Over many rounds, dishonest P gets caught. Try "Dishonest P" mode above!

P can only convince V if the statement is true.

Zero-Knowledge(ness)

In 3-coloring: V only sees 2 colours per round, from a fresh random permutation each time. V never sees the full colouring. The specific colours revealed tell V nothing about P's original solution, because next round the same vertices will show completely different colours.

V learns nothing about the statement aside from the fact that it is true.
